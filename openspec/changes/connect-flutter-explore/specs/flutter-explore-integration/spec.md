# Spec Delta

## Purpose

Menghubungkan antarmuka fitur Jelajahi pada aplikasi Flutter ke endpoint perbandingan makanan dan asisten percakapan nutrisi backend server.

## ADDED Requirements

### Requirement: Food comparison integration
The mobile application SHALL send two validated food images and structured metadata to POST /api/v1/comparisons and render the returned nutritional comparison. It MUST transmit exactly one imageA, one imageB, and valid metadata JSON with modes food or label, positive quantities, and comparison basis per_serving. It MUST NOT fabricate nutrient values or winner scores on the client.

#### Scenario: Successful comparison dispatch
- **WHEN** user selects two validated food photos and taps "Lihat ringkasan"
- **THEN** application sends multipart request to POST /api/v1/comparisons and displays the 8 comparative nutrients, B-minus-A differences, and personalized trade-offs returned by the server

#### Scenario: Comparison server rejection or failure
- **WHEN** the server returns an error such as RESCAN_REQUIRED, SCAN_BUSY, or network timeout
- **THEN** application presents an informative error dialog explaining the issue and allows the user to re-select photos without crashing

### Requirement: Nutrition assistant conversation integration
The mobile application SHALL communicate with POST /api/v1/assistant/messages using JSON payloads for general nutrition advice and 7-day pattern insights. It MUST validate that messages are nonempty up to 2000 characters, submit at most 5 completed conversation pairs in history, and display server-provided answers, sources, and warnings. It MUST NOT submit compare snapshots or send synthetic answers when requests fail.

#### Scenario: General mode consultation
- **WHEN** user submits a general nutrition question in assistant screen
- **THEN** application sends mode general with session history to POST /api/v1/assistant/messages and appends the assistant reply bubble and citation sources to the chat

#### Scenario: Pattern mode consultation
- **WHEN** user initiates "Lihat pola catatanku" from explore menu
- **THEN** application sends mode pattern to POST /api/v1/assistant/messages and displays pattern evidence and intake summaries generated by the server

#### Scenario: Assistant error handling and busy state
- **WHEN** the assistant API request fails, times out, or returns a 429 capacity error
- **THEN** application displays an error notice, preserves the user's drafted question, and permits manual retry without inventing fake AI responses
